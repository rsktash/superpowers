### (2026-08-19) Decision Beads gains a triage step; two incident parentheticals displaced here.
RULE CHANGE: forks are parked ONLY as decision beads with dep-links, and are triaged under
  precedence (ruling > code > spec > plan-time text) BEFORE being parked. Re-reading an
  inherited fork list re-runs the triage. Also: a gate's factual premises must not contradict
  the spec text they derive from or a standing ruling, not merely "evidence already gathered".

INCIDENT (why the triage step exists): solo-eb4.6.104 carried a prior session's
  "planning-round agenda" of 12 parked design forks, closing with "the epic is not dispatchable
  until every line has a ruling". The epic was dropped from an unattended overnight run on that

  Owner: "why the fuck are you being stuck with fucking gates which were written while writing
  plans? isn't the brainstormed plan and decisions made by me is the first priority?" On audit
  exactly ONE was genuinely a decision (which binding an endpoint resolves to when a chat holds
  several counterparties — customer-visible, rulable either way). Eleven were plan defects:
  a gate that never caught up with the rationale three lines above it in the same spec section
  (escalated twice, under two agenda numbers), a bead contradicting itself GET-vs-POST, gate
  vocabulary that never matched the shipped function, a Files-list omission, one answered
  verbatim by a doc comment in the source file, two sequencing errors, two security defaults
  with one safe answer, an unverified third-party API premise wanting an experiment, and four
  gates that merely lacked an owner bead. An agenda line has no owner and no dep-link, so it
  gates nothing mechanically while reading as a blocker — hence "decision bead or nothing".

### (2026-08-26) The skill is rewritten thin: unverified pins are forbidden, the citation lint replaces Self-Review, preflight stamps die.
RULE CHANGE: a task body carries intent, Files, gate, and scope fences; every verbatim fact
  (path, symbol, quoted string, locale key, commit claim) must pass scripts/lint-citations.mjs
  before bd create or must not be written — the executor resolves specifics against the live
  tree and logs deviations. Rendered-page facts are unplannable: visual gates name what to
  verify in a browser, never the DOM/CSS the planner imagines. Self-Review is deleted (author-
  blind; its catch-class is now the lint plus pre-flight's semantic residue). preflight:
  required/light stamps are deleted (sdd pre-flight runs one reader per epic, semantic classes
  only). The plan-ready marker gains its real consumer: sdd's epic gate now checks it.
  Word delta: SKILL.md 4559 -> 1990; plan-document-reviewer-prompt.md (287w, orphaned — zero
  live references corpus-wide) deleted.

2026-08-31 — context: fork.
  The skill now runs as a forked planning agent (frontmatter `context: fork`). Cause: it was
  invoked twice — once in the coordinator (loading the whole procedure into the very session the
  Venue rule exists to protect) and once in the dispatched planner — because "dispatch a planner,
  never the coordinator's session" lived inside the body and could only be read by invoking the
  skill. `context: fork` makes the harness fork on invocation: the body becomes the subagent's
  prompt, never loads into the coordinator, and covers every entry point (brainstorming handoff
  and a fresh "go with writing-plans") with no upstream routing rule. The Venue line was rewritten
  from "a dispatched planning agent" to "you ARE the forked agent" so the planner does not
  re-dispatch; Input now names `$ARGUMENTS` as the root bead id, since a fork carries no
  conversation history. Verified no manual planner dispatch existed elsewhere (brainstorming only
  "invokes", which now auto-forks) — nothing to remove.

### (2026-09-04) Amend mode restores planner-only decomposition after hand-filed plans.
RULE CHANGE: writing-plans accepts a root epic plus named child ids, plans those children in
  place, and splits an oversized child only into sibling tasks under the epic. The root's
  Attention Map and `plan-ready` marker are refreshed before the forked planner returns its
  receipt.

INCIDENT: Release 1 and Release 2 in the beads tracker executed hand-filed plans instead of
  planner products. The second-FAIL split clause also created children under a task, breaking
  the flat planner-only decomposition rule. Amend mode gives both paths a planner-owned remedy.

### (2026-09-04) The exploration map: symbol rows written once at plan time, freshness computed at dispatch.
RULE CHANGE: a new Checklist step (5, Exploration Map) writes docs/beads/<epic-id>.map.md in the
  target repo — one row per cited or created symbol, the Hash cell holding exactly one of two
  values (the 12-hex hash scripts/structural-index prints at the planning commit, or the literal
  `new` for a symbol the plan creates), seam rows for consumer interfaces, one pointer line on
  the epic body, committed with the plan. Nobody edits hashes and no bead is written to maintain
  the map; freshness is scripts/map-check's output at dispatch (owner rulings R-B and R-C on
  superpowers-35v: symbol-keyed derived data, findings never used for map changes). Amend mode
  appends the named child's rows to the epic's map file.

INCIDENT (the mining evidence behind the map): the codex mining of 64 zanjir sessions and 545
  subagents counted one fixture file read 33 times by 8 agents and one bead body read 29 times by
  14 agents — first-encounter exploration re-paid by every executor; a plan-time symbol table with
  computed freshness removes the re-read.
